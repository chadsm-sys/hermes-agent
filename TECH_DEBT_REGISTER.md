### The five headline diagnoses

1. **God-file concentration, not abandonment.** There is almost no dead code (vulture at 90% confidence: 27 hits in 1.1M lines; zero unimported modules in `agent/` or `hermes_cli/`) and almost no TODO debt. The debt is concentrated mass: six files over 10,000 lines, 90 functions over 300 lines, and one 3,982-line function on the hottest code path.
2. **Copy-paste forks instead of shared abstractions.** ~1,800 removable duplicate lines in `agent/` alone (six near-identical provider registries, sync/async fork pairs, twin Gemini adapters), ~526 lines of the same text-batching trio in 8 platform adapters, ≥ 6 independent OAuth implementations, 4 independent CDP clients.
3. **Consolidations get built but not adopted.** `gateway/platforms/helpers.py:81` `TextBatchAggregator` was written specifically to kill the batching duplication (its docstring names the five offending files) and has **zero importers**. `agent/browser_registry._resolve` is production-dead while `browser_tool.py` re-implements its policy. `hermes_cli/subcommands/` holds 38 parser builders while ~820 lines of parser blocks still sit inline in `main()`.
4. **Parallel implementations of whole product surfaces.** Three complete chat frontends (desktop 110k, ui-tui 68k incl. a vendored Ink+yoga fork, web 41k TS lines) speak the same gateway JSON-RPC dialect; two session REST APIs; four model-selection flows; five hand-synced i18n systems; slash commands implemented 3–4×, kept aligned by "Mirrors …(~line NNNN)" comments that rot.
5. **Test-suite architecture hides flakiness instead of fixing it.** CI runs every test file in its own subprocess because 178 raw `sys.modules` mutations across 82 files make shared-state runs unreliable; phantom `pytest.mark.timeout` marks are silent no-ops (plugin never installed); `tests/stress/` is unrunnable by its own opt-in flag; two test files exist as silently diverged forks at two paths.
